# Topic 4: Reviews and ratings

| Method | URL | Who |
|---|---|---|
| POST | `/api/bookings/{id}/review` `{"rating":5,"comment":"..."}` | the booking's guest |
| GET | `/api/listings/{id}/reviews` | everyone |

## A review belongs to a stay

[`Review`](../../../airbnb-backend/src/main/java/jbdl/airbnb/reviews/Review.java) points to the
**booking**, not only to the listing. That makes the important rules easy to enforce:

| Rule | Where |
|---|---|
| only the guest who stayed | service: 403 |
| only a stay that took place (not cancelled) | service: 409 |
| from the check-out day | service: 409 |
| once per stay | service: 409, and `booking_id unique` in the database |
| rating 1 to 5 | `@Min(1) @Max(5)`: 400, and `check (rating between 1 and 5)` in the database |

The schema Hibernate generates (real output):

```sql
create table review (rating integer not null, booking_id bigint not null unique,
    created_at timestamp(6) with time zone not null, id bigint generated by default as identity,
    listing_id bigint not null, comment varchar(1000), primary key (id),
    constraint ck_review_rating check (rating between 1 and 5))
```

`listing_id` is stored too, although the booking already knows the listing: "all reviews of a listing"
is the common question, and it needs no join through `booking` this way (and has its own index).

## The average

The database computes it
([`ReviewRepository`](../../../airbnb-backend/src/main/java/jbdl/airbnb/reviews/ReviewRepository.java)):

```java
@Query("select avg(r.rating) from Review r where r.listing.id = :listingId")
Double averageRating(long listingId);
```

`Double`, not `double`: with no reviews, `avg` is `NULL`, and the answer says `"averageRating": null`
rather than a misleading 0. [`ReviewService`](../../../airbnb-backend/src/main/java/jbdl/airbnb/reviews/ReviewService.java)
rounds it to one decimal (4.666… → 4.7) with `BigDecimal`.

The guest is shown by first name only; the email never leaves the API.

## Tested

[`ReviewApiTest`](../../../airbnb-backend/src/test/java/jbdl/airbnb/ReviewApiTest.java) stores past stays
directly (the booking API only books future ones): two reviews give 4.5, newest first, readable without a
login; no reviews give `null` and 0; only the guest, only once, not before the check-out day (but on it),
not for a cancelled booking; rating 6 is 400; no login is 401.

## Interview questions

- **Why tie a review to a booking?** Only real guests can review, once per stay, and the rules become
  simple checks on one row.
- **Compute the average on every read, or store it?** Computing (as here) is always right and cheap with
  an index. With millions of reviews, store a running average and count on the listing, updated with each
  review, or cache it (Session 15).
- **Why is the average `null` with no reviews?** "No rating yet" and "rated 0" are different facts.
