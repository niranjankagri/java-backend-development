## Why this shape

- **Shares as rows, not a formula.** Storing "Ravi owes 300 of Dinner" makes every split type the same
  for balances: a balance is just *paid − owed* summed over rows. EQUAL, EXACT and PERCENT differ only
  in how the shares are calculated when the expense is created (Session 13).
- **Settlements separate from expenses.** A repayment isn't a cost; keeping it apart makes reports
  ("what did the trip cost?") simple.
- **Append-only.** Nothing is updated in place; corrections are new rows. The balance can always be
  re-calculated from the history.
- **Exact money.** `numeric(12,2)` + `BigDecimal`.
- **`split_type` as text.** `@Enumerated(EnumType.STRING)` stores `'PERCENT'`, not a position number
  (test `enumStoredAsText`).

## Real schema generated by Hibernate (excerpt)

```sql
create table app_user (id bigint generated by default as identity, name varchar(100) not null, email ... unique, ...)
create table expense (amount numeric(12,2) not null, ...)
create table group_member (group_id bigint not null, user_id bigint not null, primary key (group_id, user_id))
alter table if exists expense add constraint FK... foreign key (group_id) references expense_group
alter table if exists expense add constraint FK... foreign key (paid_by_id) references app_user
alter table if exists expense_share add constraint FK... foreign key (expense_id) references expense
alter table if exists settlement add constraint FK... foreign key (from_user_id) references app_user
...
```

Every relationship became a foreign key, so the database itself refuses an expense in a group that
doesn't exist.

## Interview questions

- **How would you model a many-to-many with extra data (e.g. "joined at")?** As its own entity (`GroupMembership`) instead of `@ManyToMany`.
- **Why store shares instead of calculating them on the fly?** One balance formula for every split type, and history that doesn't change when rules change.
- **Why avoid updating expenses in place?** An audit trail: balances must be explainable.
- **What indexes would you add?** On foreign keys used in lookups: `expense.group_id`, `expense_share.user_id`, `settlement.group_id`.
